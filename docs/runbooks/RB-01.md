# RB-01 — Model provider unavailable or slow

Source: HLD v0.5 §9.1. Exercised by the degradation suite (§10.2) by following these steps.

**Two rules hold in every runbook.** Never restore service by weakening a control (disabling the
sandbox, relaxing a budget, raising a rate cap, skipping a check, hand-editing a bundle). A needed
change goes through change control (plan §17.1). `handed_off` episodes are never reopened.

| | |
|---|---|
| Trigger | Model provider unavailable or slow |
| Automatic behaviour | In-flight episode -> handed_off with the signals gathered so far; alert. Sentinel and verifier continue. After P-29, and only if a pre-approved fallback bundle exists, the controller activates it for new episodes (audited, alerted). |
| Operator actions | Diagnose from watchtower and the handed-off signals. Check provider status. Never hand-edit providers.yaml to switch provider. |
| Exit condition | A probe step on the primary configuration completes; `active` is returned to the primary bundle through the normal activation process. |
| Where to look | model-broker meter `upstream_errors`; `valops alerts` |
