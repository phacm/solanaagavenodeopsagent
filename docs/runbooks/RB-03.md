# RB-03 — Bundle integrity failure

Source: HLD v0.5 §9.1. Exercised by the degradation suite (§10.2) by following these steps.

**Two rules hold in every runbook.** Never restore service by weakening a control (disabling the
sandbox, relaxing a budget, raising a rate cap, skipping a check, hand-editing a bundle). A needed
change goes through change control (plan §17.1). `handed_off` episodes are never reopened.

| | |
|---|---|
| Trigger | Bundle integrity failure |
| Automatic behaviour | Observe-only: no LLM step; high-severity alert naming the changed path. |
| Operator actions | Notify the security reviewer. Compare the bundle with its signed manifest (`valops bundle verify <id>`). Do not re-point `active` until the cause is known. Then roll back (`valops bundle rollback`) or revoke. |
| Exit condition | A verified bundle is active and the integrity check passes at process start; then `valops observe-only clear`. |
| Where to look | `observe_only.json`; alert text |
