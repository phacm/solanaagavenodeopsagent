# RB-10 — Chain verification fails

Source: HLD v0.5 §9.1. Exercised by the degradation suite (§10.2) by following these steps.

**Two rules hold in every runbook.** Never restore service by weakening a control (disabling the
sandbox, relaxing a budget, raising a rate cap, skipping a check, hand-editing a bundle). A needed
change goes through change control (plan §17.1). `handed_off` episodes are never reopened.

| | |
|---|---|
| Trigger | Chain verification fails |
| Automatic behaviour | Observe-only; critical alert; chain and newest anchor preserved. |
| Operator actions | Treat as possible tampering; the security reviewer leads. Do NOT truncate or repair the chain. Rotate chain keys after the investigation. |
| Exit condition | Written clearance from the security reviewer under change control; then `valops observe-only clear`. |
| Where to look | `valops chain verify` errors |
